# 拾光完整分镜初始化 JSON 2.0.0

用于完整分镜生成与整份重新初始化。当前默认合同修订为 `2026-11-04-json-v2`，只返回一个 JSON 对象；不返回表格、代码围栏、解释或文件链接，不创建目录、运行脚本或操作数据库。应用负责解析、检查、保存与导入。

## 与应用格式对齐

- 使用随包的 [initialization.schema.json](initialization.schema.json)。它对应应用 `server/storyboard/initialization.schema.json` 的 2.0.0 初始化输入格式；不是数据库标准导出 `schema_version:1.0.0`。
- 调用方已经提供本轮冻结的字段规范、Schema 与剧本时，直接使用这些内容；不要为加载参考或保存输出而申请文件、命令、MCP 等工具。
- `格式版本` 必须是 `"2.0.0"`，`完整分镜` 必须为 `true`。完整稿至少一场一镜，每场非空；覆盖全部剧情与结尾，不用省略号或占位内容替代后半部。
- 用户只要片段、讨论或视频提示词时遵守其请求，但片段不属于可自动完整初始化的结果；不得给片段加 `完整分镜:true`。
- JSON 中不包含数据库永久 ID、旧项目 ID、路径、工具参数、导入请求编号或锁。已有资料与图片的保留及名称匹配由应用负责，模型不执行删除或替换。
- 下列示例中的代码围栏仅用于文档说明；实际模型最终回复没有围栏。

## 字段约定

| 层级 | 新生成结果填写的字段 |
| --- | --- |
| 顶层 | 格式版本、完整分镜、项目名称、故事核心、画幅、总时长秒、素材清单、场景 |
| 素材清单 | 人物、场景、道具三个对象数组；无相应素材时填 [] |
| 清单条目 | 编号、名称；可加描述，人物可加年龄、身份、人物特点 |
| 场次 | 场次、地点、场景编号、时间、内外景、空间设定、开始秒、结束秒、时长秒、镜头 |
| 镜头 | 镜号、开始秒、结束秒、时长秒、景别与角度、画面与人物动作、摄影机设计、人物编号、道具编号、声音与对白、剪辑衔接 |
| 声音与对白 | 环境与动作声、对白数组；有跨镜台词时增加承接对白 |
| 对白 | 人物编号、人物、声源、台词、表演要求 |
| 承接对白（可选） | 来源镜号、说明；指向先前镜头中的最后一句实际对白 |

- 可补充顶层 `人物` 资料数组，使用 `姓名`、`年龄`、`身份`、`人物特点`；姓名必须在人物清单内，且同一角色只出现一次。不填该数组时应用从清单生成资料。未知年龄省略，或用明确的“未明确”，不写 Schema 不接受的 null，不编造关键身份。
- 可以使用 `全片设定`、`连续性与时长锁定`、`时间轴说明` 等当前导入器保留的扩展字段。调用方更严格的输出 Schema 未包含这些字段时，把必要信息融入空间、动作、摄影、声音与衔接字段，不另发说明。
- `故事核心` 保留原作的核心事件与因果；不能代替逐场分镜。原剧本及用户要求以应用保存的任务输入快照为依据。
- 每镜长文本保留完整动作顺序、微表演、摄影、声音及衔接，不压缩成仅镜号、情绪词或一句概述。

## 清单与明确引用

- 人物编号如 `C01`，场景编号如 `L01`，道具编号如 `P01`，仅在本 JSON 内使用。各条目编号唯一；同类名称经 Unicode NFC、去首尾空格与英文字母大小写归一后不可重复。人物按身份、场景按实际空间去重，不能为每镜重复建人或地点。
- 场次使用 `场景编号` 关联场景清单；本镜换到其他明确空间时可在镜头填写自己的 `场景编号` 覆盖该镜关联。它们不等于顺序 `场次` 数字。
- 镜头 `人物编号` 列出该镜明确关联的清单人物，包括需要关联的仅声音角色；以动作和对白的声源说明谁出镜、谁只有声音，不能让画外角色凭空出现在画面。
- 镜头 `道具编号` 只引用道具清单内本镜实际涉及的关键物件。普通物品可以只写在动作或空间描述中，不强制独立建档。
- 对白 `人物编号` 与 `人物` 姓名必须属于同一个清单人物。无台词时 `对白:[]`，无关联人物或道具时相应数组为空。纯旁白、电话或画外说话人也要有明确人物条目及声源，不能用未登记的名字。
- 应用不会从地点简称、清单排列次序或长段动作文字猜测全部关系。因此清单条目与正文描述一致还不够，必须填写结构化编号引用，才能可靠查看资产关联镜号。
- 清单不代表自动生成参考图。关键道具只挑外观承担情节、揭晓或跨镜身份连续性的物件；普通餐具、门锁、家具等通常随人物或场景表达，不因出现特写就必须独立建档。场景的日夜或布置变体由剧情需要决定，不把每镜、每次时间变化都拆成新资产。

## 时间轴与对白承接

- 镜号使用全片唯一的递增字符串，如 `"01"`、`"02"`；场次从 1 连续排列。编号用于本次 JSON 的顺序和引用，不是应用永久 ID。
- 所有时间为有限数字，单位秒，最多三位小数。每镜时长大于 0；第一镜从 0 开始，后镜开始等于前镜结束；每镜 `结束秒 = 开始秒 + 时长秒`。
- 场次起止等于其第一镜和最后一镜，场次时长为镜头时长合计。项目 `总时长秒` 等于最后一镜结束及全片时长合计。先分配可表演的时长，再统一累计，不靠相互矛盾的手填时间。
- 现有通用导入器可能警告并重算旧输入时间；新自动生成不得依赖这种纠错掩盖错误，应在替换前严格校验并指出具体场次、镜头和字段。
- 跨镜台词只在开始镜的 `对白` 中保存一次，承接镜 `对白` 只含新句。承接使用 `声音与对白.承接对白` 对象，`来源镜号` 必须指向先前有对白的镜头，当前兼容导入器关联的是该镜最后一句对白；`说明` 写清延续位置和结束状态，不重复完整语句作为新对白。
- 需要承接非最后一句、同时承接多个来源或更复杂并行声音时，现有中文承接格式不能准确表达全部关系。先按自然切点重新拆镜，或等待应用明确扩展协议；不要编造看似结构化但导入器不会识别的新承接字段。
- 音画并行不重复累计；转场、停顿、字幕独占画面及淡出占时计入总长。遵守用户片头片尾口径，不强制无 BGM、80 秒、28 镜或样例风格。

## 交付前内部复核

1. 一个标准 JSON 对象，没有其他结果或工具调用；无重复键、非法数字、注释、尾逗号、代码围栏或占位。
2. 格式版本、完整标志、三类对象清单、场次与镜头完整；各编号唯一，引用存在且类别、姓名一致。
3. 镜头动作、摄影、声音和衔接完整，台词不遗漏或重复；承接源在前且确有对白。
4. 各镜正时长、全片连续时间、场次范围及总长一致；动作和台词实际可完成。
5. 原剧本关键事件及结尾覆盖完整。JSON 可解析或 `完整分镜:true` 本身不能证明剧情没有遗漏，也不能证明动作、情绪与台词合理。
6. 仅返回结果，不声称已保存、已导入、已替换或已生成图片。历史 `scripts/save_storyboard.py` 仅保留给明确要求旧格式手动导出的任务，不用于本 2.0.0 合同或网页生成流程。
