# 完整分镜初始化 JSON 2.0.0

本规范替代同目录旧版多文档 / 快照方案。只描述一次性完整初始化的输入；导入后数据库为编辑依据。现有中文分镜和标准 `.storyboard.json` 均兼容。

## 字段约定

- `格式版本` 若提供，必须为 `2.0.0`，同时 `完整分镜` 必须为 `true`。显式 `complete:false`、`完整分镜:false` 或片段文档一律拒绝。
- `素材清单` 三个数组必须齐全；没有人物或道具用空数组。同类型名称经 NFC、去首尾空白和英文字母小写后不可重复。
- 新版清单对象使用 `编号`、`名称`，人物也接受 `姓名`。兼容既有清单字符串数组。编号用于本文件内部引用；不要求跨重新初始化保持不变。
- 可保留详细顶层 `人物` 数组，姓名必须在人物清单中且不能重复；省略时从清单构造。未知字段、原剧情和原对白仍保留在来源。
- `场景编号` 关联场景资产，可写在场次上；镜头写该字段时覆盖本镜的场次关联。`人物编号`、`道具编号` 为数组，引用本文件同类清单编号。
- 对白支持 `人物编号`，兼容旧 `人物` 姓名。两者同时提供时必须相符。已知对白说话人会建立结构化人物关系；不推断其他画面人物。
- 没有明确编号时，仅创建并保护清单资产，不按清单顺序、地点简称或长动作文字猜测场景和道具。用户可在编辑器手动关联。
- `场次`、`镜号` 和起止秒数是可读的导入数据。镜头时长以 `时长秒` 为准累计；时长不一致在预览提示，原始数值仍在来源中保留。单镜须大于 0，最多三位小数。初始化界面展示完整场数 / 镜数 / 时长，但程序不能证明剧情已完整结束。
- 必须至少一场一镜，各导入场次须有镜头。手动编辑后允许暂存空场次或无镜头草稿；完整重新初始化仍须提供完整结构。
- 不新增造型、图片或场景状态必填项，也不要求为全部道具生成参考图。

## 绑定与导出

初始化按已选普通项目的当前活动名称匹配，输入中的任何数据库编号、旧项目编号和来源映射都不能越过名称匹配。已有档案保留自己的资料，新 JSON 只初始化新建档案。

入库后人物 `characters[].id`、场次 / 镜头的 `scene_asset_id` 和镜头 `prop_ids` 是项目资产库永久编号；镜头 `id`、对白 `id` 日常编辑保持稳定。`asset_manifest.character/scene/prop` 保存完整清单，数据库关系表同步维护保护。

标准导出沿用兼容编辑模型 `schema_version:1.0.0`；这是编辑模型版本，不是中文初始化的 `格式版本`。标准 Schema 在 `server/storyboard/project.schema.json`，同源 `/api/storyboard/schema` 可下载。标准导出新增 `document_id`、`bound_project_id` 和 `asset_manifest`。重新初始化时仍重新按名称绑定；完整备份恢复才保留原数据库编号。

原文件不被修改。完整备份不含原始媒体文件；可发送给他人的全媒体资产包本期不做。
