# 拾光 · 本地素材库

分享包请先读 **[START_HERE.md](START_HERE.md)**；其他 AI 先读 **[AGENTS.md](AGENTS.md)** 和 **[AI_HANDOFF.md](AI_HANDOFF.md)**。新安装默认内置 SQLite，不需要 MySQL，初始为空素材库。

普通分享版安装 Node.js 22.x 后，运行 `npm run setup` 和 `npm start`，也可用 `启动分享版.command`（Mac）或 `安装并启动.cmd`（Windows）。分享模式数据在项目 `data/`。源开发目录保留的 `启动素材库.command` 和旧 `npm start` 可能连接已有库，测试分享模式请用 `npm run portable`。更多环境差异、Docker 方式和未实测平台说明以 START_HERE 为准。

FFmpeg/FFprobe 用于波形、参数与兼容预览，ExifTool 用于拍摄日期；缺少时相关功能降级。Mac 照片转换使用 sips，废纸篓组件需要 Swift 编译工具。

## 真实文件夹视图试用

“分类管理”顶部可切换“文件夹视图 / 旧分类视图”。新版按真实文件夹展示多级树、子目录入口、面包屑和目录内标签检索，不迁移或删除旧分类，不改动原文件。不满意时切回旧分类即可。当前阶段没有解决外部移动后的素材身份迁移；详情与代码回撤步骤见 [FOLDER_VIEW.md](FOLDER_VIEW.md)。

## 界面风格

侧栏顶部的滑块按钮打开「界面设置」，可在 **森林绿（默认）/ 深色 / 午夜蓝 / 暖褐纸质 / 极简灰白 / 海洋青** 六套风格间切换。点选即时生效（只改 `<html data-theme>` 与 CSS 变量，不触发任何请求），选择记在本机浏览器 `localStorage` 的 `shiguang.theme`，刷新后保持；深色风格下首帧前就会套用，不会闪白。

配色由脚本生成：`src/style.css` 里的色值写法统一是 `var(--c-xxxxxx)`，`src/themes.css` 存放各风格的取值，`src/theme-list.ts` 是前端读到的风格清单（后两者都是生成文件，不要手改）。**新增或调整风格 = 改 `scripts/theme-gen.mjs` 里的 `THEMES` / `OVERRIDES`，再运行 `node scripts/theme-gen.mjs`**；若之后往 `style.css` 里又写了硬编码色值，用 `node scripts/theme-gen.mjs --tokenize` 重新纳入 token（会先把原文件备份到 `backups/source/`）。

## 外部整理与清单文件（.shiguang/manifest.json）

**直接改文件系统（访达、终端、脚本、GPT）是这个库的正常用法**，不是"违规操作"。为此权威方向是：

| 数据 | 权威在哪 |
|---|---|
| 文件存不存在、现在在哪个路径 | **文件系统** |
| 素材身份（id）、标签、备注、分类、收藏、拍摄时间 | **登记根下的 `.shiguang/manifest.json`** |
| 时长/编码/缩略图、界面查询用的索引 | SQLite —— **纯投影，可随时重建** |

因此：

- 在访达里**改名、移动、连整个子目录一起搬走**，应用会**在 1~2 秒内自动接上**（后台监听 → 精简对账），素材 id、标签、备注、项目关联都不变，也不会多出重复记录。应用没开时做的整理，会在下次启动对账时接上（必要时手动点一次对账接口）。
- 匹配逐级降级：**路径 → dev:ino → 文件扩展属性里的 id → sha256 → 同名同大小（且唯一）**。所以跨盘搬运、复制后删除也能认回来。
- **绝不自动删除**：文件真的没了，只把记录标为离线（进"离线素材"），并在清单里留 `state: "missing"` 痕迹。
- **数据库丢了也不怕**：换机、清库、重建索引后，标签与备注会从清单恢复（已实测）。
- 清单是**给人和 AI 看的 JSON**：可以直接读、可以改（改前建议备份）；想让它反过来覆盖数据库就用 `--importMetadata`。默认方向是"数据库 → 清单"镜像，**并且在界面里保存标签/备注/分类后约 1 秒内自动刷新清单**（防抖合并批量编辑），所以 GPT 读到的是最新值，而不是上次对账时的旧值。
- 相关开关：`MEDIA_SKIP_RECONCILE=1` 关闭对账；`MEDIA_NO_WATCH=1` 只对账不监听；`MEDIA_RECONCILE_HASH=1` 启动时顺便补 sha256。
- 接口：`GET /api/reconcile` 看各根的对账版本与监听状态；`POST /api/reconcile`（可带 `{rootId, importMetadata, hash}`）立即对账。
- 首次启用/迁移旧库：`node scripts/export-manifest.mjs`（加 `--hash` 顺便补哈希，`--dry-run` 只预览）。它会为每个登记根写出清单，并立即对账一次。
- 局限：网络卷与 exFAT 没有扩展属性、文件系统事件也不可靠，此时退化为"启动对账 + 每 5 秒兜底"，其余能力不变；**zip 归档会丢掉扩展属性**（实测），所以身份与标签要靠清单本身随目录一起走。

## 使用

- 分享版不会带入作者的素材索引；在“添加素材目录”中选择或填写你自己授权的文件夹，并指定类型。
- 音乐目录新增文件按第一层子目录归类，直接放在登记目录的文件使用该目录名称。有音轨的 MP4 等容器会按实际音轨纳入音乐，重扫不会覆盖人工指定类型或已有分类。NCM 只建立可检索索引，明确标为不能直接试听，不尝试解密或改写原文件。
- 选择素材可试听、预览、修改标签和备注。时长筛选依赖后台参数读取；未读取的素材可用“时长未读取”筛选找到。
- 创建日期可按起止日期筛选（含结束当天），支持只填一端，按北京时间计算；详情和导出清单显示创建时间，也可按创建时间排序。时间来自文件系统 birthtime，不是修改时间或照片的 EXIF 拍摄时间。复制或下载素材可能改变其创建时间；不可读取的时间保留为未知，不会用修改时间替代。
- 日期类型选择“拍摄日期”可搜索照片/RAW 的 DateTimeOriginal 和视频内嵌日期，需安装 ExifTool。有时区的时间换算为北京时间，无时区的照片时间按北京时间解释并注明。视频只有 QuickTime CreateDate 时显示“视频容器时间，可能为导出时间”，不能保证等于实际拍摄时间。没有内嵌日期时标为未知，不用文件日期补替；详情可手动校正索引中的拍摄时间，不写入原文件。清空校正输入并保存会重新读取内嵌日期。重扫保留手动校正，相机时钟错误需人工核对。
- 批量操作针对当前勾选项。批量改名增加前缀；移动只能选择已登记目录及其中已存在的子目录。
- 修改原文件前需要检查目标路径，再确认操作。不会覆盖同名文件。
- “操作记录”可撤销移动、改名和废纸篓操作；需从最近一次操作开始恢复。若原位置已有文件、原目录不可访问或废纸篓已清空，恢复会被拒绝。
- “分类管理”现统一管理音乐、音效、视频和照片，可按类型筛选，支持公共分类新建、改名、删除及批量设置主分类。每份素材支持一个主分类和多个额外分类；设置分类弹窗勾选或取消额外分类后事务保存，不改变标签、备注、访达次数及待确认状态。设置主分类保留额外归属；清空全部分类需确认。“移出当前分类”只移除该归属。公共分类改名、删除对所有类型生效，不删除或移动原文件。为保留旧分类 ID，底层兼容沿用 `music_categories`、`music_category_links`，两表现用于所有类型；主分类及旧子类仍保存在 `assets.category`、`assets.sub`。通用接口为 `/api/categories`，旧接口保留兼容。空分类在管理中保留，不出现在动态筛选中。升级前快照位于应用数据目录 `backups/before-unified-categories-*.json`。

## 数据与限制
旧分类系统中，主分类只能从已存在的分类下拉选择，素材详情、完整编辑、批量修改及分类保存接口均校验；输入不存在名称会拒绝整次修改，不隐式创建分类。新增分类通过“旧分类视图 → 新建分类”，或在已登记素材目录下创建子文件夹后重新扫描（空文件夹也登记，隐藏目录及链接不导入）。新入库素材按前两级子文件夹归类；重扫保留既有分类。子类具有所属主分类 ID，后端校验父子归属；素材记录仍按主类、子类名称存储。新版真实目录浏览不受这个二级结构限制，也不会自动转换旧分类数据。

“设置与缓存 → OpenAI 音乐分析”配置 API Key，也可在音乐分析区域的设置图标中配置。使用支持音频输入的 `gpt-audio-1.5`。API Key 采用 AES-256-GCM 加密后保存在当前主数据库的 `app_secrets` 表中，不明文保存于数据库，不返回网页。独立解密密钥位于本机应用数据目录的 `secrets-master.key`，权限 0600；必须单独安全备份，丢失后无法解密既有 API Key。数据库与解密密钥同时泄露仍会暴露 API Key，不等同于系统钥匙串保护。旧 `openai-audio.json` 仅在成功迁移并校验后删除，失败时保留原文件和数据库密文。保存设置不会调用 API。MySQL 连接密码属于启动连接配置，仍保存在数据库外，不放进其自身数据库。

“测试连接”用已保存的 Key 请求 OpenAI 的模型信息接口，不上传音频、不发起模型生成，不自动重试。通过只代表当前 API 认证与模型元数据访问正常，不能验证音频端点权限、余额或付费额度。连接失败会展示已脱敏的原因和状态码。“查看诊断日志”可筛选、展开、刷新、导出 JSON 或确认清空。日志保存在当前主数据库的 `openai_diagnostics` 表中，记录连接测试及音乐分析的成功、失败和缓存命中；包含时间、阶段、状态码、已知错误码、请求编号、耗时、素材 ID 和片段范围，不包含 Key、Authorization、音频、文件名/路径、提示词、分析内容或原始远端错误正文。最多保留 1000 条且仅展示最近 30 天，写入时清理过期条目。历史旧报错无法追溯恢复，日志从此版本启用后开始记录。JSON 导出到用户选择的下载位置，不自动上传给任何服务。

“连续标记音乐”以及普通音乐详情的“分析音乐属性”可选择起点与 15/30/60 秒片段，默认 30 秒。只有主动点击分析才将该片段发送到 OpenAI，需 API 账户及对应模型访问权限，费用按 OpenAI API 计费，不承诺账户一定可用。不会上传完整音乐、文件名、本机路径或其他素材。片段在本机转成 WAV 后发送，不覆盖原文件，任务结束后清理临时文件。NCM、离线及损坏音乐不能分析。不提供自动批量上传。

AI 结果仅针对片段，展示情绪、风格、乐器、节奏、强度、用途和限制，不保证音乐理解准确，不用模型猜测作为精确 BPM。勾选建议并采用后只放入编辑区，可选追加建议备注，仍需点击保存；不会自动设为“人工确认”。缓存保存在当前主数据库的 `music_analyses`，依据素材 ID、文件大小/修改时间、模型、片段范围与分析版本复用。打开界面只读取缓存，重复分析须再次确认费用。失败不自动重试，超时或网络错误不保证远端未计费；同时只允许一个实际分析任务。移除 API Key 不移除既有缓存。

“标签管理 → 连续标记音乐”只处理未标记的音乐，按文件修改时间由近到远排队。在同一页试听、勾选常用或自定义标签、填写可选备注，再点击“保存并下一首”；相似音乐可沿用上一首标签。标签选项中的情绪词只是手动选择建议，不代表自动识别结果。保存到本机数据库，不修改原文件；保存失败保留编辑内容。跳过项仅在本轮暂缓，可重新查看，退出后不保留跳过名单。扫描入库的新增未标记音乐会进入同一队列，下一首读取最新结果，队列为空时每 5 秒检查一次。已有标签的音乐不重复入队；NCM 和离线音乐仍可标记，但不能试听。

“标签管理”覆盖全部媒体，自动收录素材的现有标签，支持保留空标签、新建/改名/删除标签、查看关联素材及未标记素材、批量添加或移除标签。标签关联仍以 `assets.tags` 为准，空标签注册表保存在 `asset_tags`；改名和删除会同步更新所有关联素材，不写入媒体文件。标签筛选为完整标签精确匹配，不把“风”与“大风”混在一起。

第一阶段选材工作台：搜索结果默认只显示收藏和“更多素材操作”，访达、标签、分类和废纸篓操作收进菜单；“完整操作”可恢复原来的快捷按钮，并记住本浏览器的选择。“全部标签”和“标签组合”合并为一个标签筛选入口，可搜索并连续勾选；单选也是同一入口。支持同时包含全部、任意包含一项、排除任意项，三组条件之间为 AND，与关键词、目录、类型及日期过滤共同生效，每组最多 20 个精确标签。同一标签改选至另一组时会移除原组条件，避免同时包含又排除。已选条件可逐项移除或清空，只影响查询，不修改素材标签。

“项目”是独立导航项，支持新建、改名、备注、软件选择（剪映/达芬奇/其他）及确认删除。顶部选择当前项目，素材操作菜单或批量工具栏可将照片、视频、音乐和音效加入候选，同一素材可属于多个项目，每个项目内只保留一条关联。候选/已使用分栏，一键或批量标记使用、退回候选，支持项目内搜索、使用位置备注、分页、试听及访达定位。素材详情与编辑弹窗展示跨项目使用历史；首次确认使用时间保留，重复标记不重复累计，试听和访达次数不当作使用。项目及关联保存在当前主数据库的 `media_projects`、`project_assets`，MySQL 迁移保留；当前项目选择仅作为本浏览器偏好保存。移出项目或删除项目不动原文件、不改原分类标签收藏；离线、废纸篓或索引清理仍保留已加入时的素材快照及使用历史。首版记录来源为手动确认，不读取剪映草稿、不读取达芬奇时间线，也不自动复制、导出或判断版权。

试听播放器支持上一首/下一首、波形点击跳播、临时入出点、循环选段及收藏。“连续试听”默认关闭，开启后自然播放结束自动播放当前筛选结果中的下一条，支持跨分页，跳过离线、NCM 和非音频项，最后一条结束停止，不绕回开头；仅记住本浏览器的开关偏好，刷新不会自动开始播放。连续试听与循环选段互斥，收起选段时仍能操作连续试听。跨页等待期间关闭播放器、暂停、切换素材或筛选会取消过时请求。分类管理、标签管理和重复检测使用各自列表，不套用搜索结果的切歌队列，连续试听开关在这些页面禁用。列表焦点下空格播放/暂停，上下键切歌；输入框、选择器、菜单、对话框和中文输入过程中不触发全局试听快捷键，按钮保留原生键盘行为。手机点击试听不会自动展开详情遮住列表。关闭编辑弹窗返回时保留当前筛选、试听位置及列表滚动位置。筛选后不再匹配的素材正常退出结果，不强行保留在错误结果里，也不自动清空筛选条件。切歌重置选段，选段仅供试听，不写入媒体文件；浏览器循环不保证采样级精度。快速切歌造成的预期 AbortError 不作为播放失败。此阶段不包含项目素材篮、版权管理或音频转码分析的新功能。

分类采用两级结构：主分类保存在 `music_categories`（兼容旧表名，覆盖全部媒体），子类保存在 `asset_subcategories`，以 `category_id` 绑定主分类；同一主分类下子类名唯一，不同主分类可各有同名子类。素材的 `category/sub` 保留可读名称，但所有编辑接口都会校验其父子归属，不允许自由填写不存在的子类。首次启用先备份旧分类字段到 `backups/before-category-hierarchy-*.json`，按已有主类/子类组合迁移并记录完成标记；历史无主类的子类集中保留在“历史未归类”下。切换主分类时清空旧子类，子类可留空；分类管理中选择主分类后可新建、改名、删除和筛选子类。子类改名同步关联素材，删除只清空子类，删除主分类则同时清空其素材的主类和子类，均不改动原文件。额外分类仍是独立的多分类归属，不代表二级关系。新扫描目录以登记目录下第一层为主类、第二层为子类，更深层沿用这对分类；已有素材重扫保留人工分类，不按目录重新覆盖。

“重复音频”为独立导航项，可选择音效、音乐或全部音频，先核对真实文件大小，再对候选文件流式计算 SHA-256，按字节内容一致分组；不检测转码、变速、音量变化或截取版本的听感相似性，也不验证媒体是否可解码。空文件、离线、越界链接或检查期间变化的文件会列出原因并跳过。各范围最近一次完整报告及校验缓存保存在当前主数据库 `duplicate_audio_reports` 中，依据真实路径、根目录身份、设备号、inode、大小、修改时间和变更时间复用；勾选“重新计算校验值”可绕过缓存。取消或失败保留上一次完整报告，不自动删文件。支持进度、搜索、分组试听、访达定位和 JSON 导出。

“标记重复音频”需确认，为结果中的所有副本（不只额外副本）追加普通标签“重复音频”，保留其他标签、分类、备注及人工确认状态；原标签先备份到应用数据目录 `backups/duplicate-audio-tags-*.json`。标记前再次核对整组文件；任一文件变化、离线或标签达到上限时整组跳过。重复标记不叠加标签。网页成功移入废纸篓后会同步相关重复组：剩两份及以上保留标签，仅剩一份移除该素材的“重复音频”标签，不改其他标签、备注或分类；合并所有检测范围判断，离线、改名和改类型不算删除。同步前备份到 `backups/duplicate-audio-tag-cleanup-*.json`，备份失败保留原标签并显示警告，不把已成功的文件删除误报为失败。网页外删除需先确认清理索引，本次不自动处理；撤销恢复文件后可重新检查并标记重复音频。额外副本大小是逻辑大小，并非必然能释放的物理磁盘空间。

重复音频列表每个文件提供访达定位和删除按钮。删除复用原有操作预览、目标路径核对及确认流程，只移入 macOS 废纸篓，可在“操作记录”中撤销；不根据重复组自动挑选要删的副本。成功后刷新结果和统计，已移入废纸篓、索引已移除或原路径已改变的记录不计入当前分组，不足两份的组不再显示；报告保留检测时间及历史快照，撤销恢复后刷新即可重新展示，文件内容发生变化则需重新检查。定位操作继续累计访达次数。检测、标记、文件操作中或离线素材禁用删除；仅因筛选或路径变化而隐藏的组不会触发标签清理。
搜索结果中的音乐也可点击行末“添加到其他分类”；选中音乐后，搜索栏右侧提供相同的快捷入口，保留原分类并自动排除重复添加。

预览缓存、日志和本机数据库连接配置保存在 `~/Library/Application Support/拾光素材库`，不上传网络。未配置 MySQL 时继续使用原 SQLite 索引；迁移成功后，目录、素材信息、标签、备注、收藏、拍摄时间和操作记录全部只读写本机 MySQL。旧 SQLite 留作迁移前归档，不做双写；MySQL 不可用时不自动切回旧库。应用不自动扫描整台电脑，不遍历符号链接或隐藏目录。已有分类目录中的链接不会重复入库。

## 本机 MySQL

在“设置与缓存 → 本机 MySQL”填写本机地址、端口、独立数据库名、账户和密码，测试连接后点击“迁移并启用 MySQL”。默认使用 `127.0.0.1:3306` 和新数据库 `shiguang_media`。只有迁移启动时需要创建数据库/表的权限；运行时需该库的 SELECT、INSERT、UPDATE 权限。推荐之后使用仅限此库的专用账户，不在网页或聊天中公开密码。

迁移暂停写操作与元数据队列，先生成 `backups/before-mysql-*.sqlite`，在 MySQL 事务内导入，再逐表核对所有原始字段的 SHA-256。校验成功才启用 MySQL。已有同名表或其他素材库绑定的数据库会被拒绝，不覆盖。保留原始操作顺序以继续支持撤销。原始媒体文件不迁移、不转码、不改动。

本机连接密码保存在应用数据目录的 `mysql-connection.json`，文件权限为 `0600`，仅当前 Mac 用户可读写；这不是加密保险库，服务器不会把已保存密码返回网页。备份该文件时需按敏感文件处理。修改 MySQL 密码后也需更新该连接文件，不能把旧 SQLite 当作最新数据。

MySQL 驱动通过专用工作线程执行查询，保留既有文件操作的同步事务边界；超时不会自动降级到其他数据库。独立数据库验收 `node scripts/test-mysql-local.mjs` 使用临时 MySQL 实例（需 `/usr/local/mysql/bin/mysqld`），覆盖迁移、真实写入、特殊字符搜索、事务回滚、改名撤销和重启，完成后删除测试实例。

改名、移动或移入废纸篓会改变原文件位置，可能让已有剪映/AE 项目及之前的分类链接失效。需要保持项目引用时，请只修改标签、收藏和备注。

媒体兼容预览按需生成。RAW 预览依赖 macOS 对相机格式的支持，不保证全部相机格式可预览；失败时保留索引和原路径。受保护、损坏或无视频流的媒体可能无法生成代理。

部分失败逐项记录，中断操作标为“需核对”，不自动删除文件。日志不是原文件备份。不要同时在访达和网页中修改同一个文件。

网页先显示数据库中的素材，后台仅检查文件状态，不自动清理记录。每个文件的状态、检查时间、原路径及目录身份保存在当前主数据库，缓存有效期为 10 分钟，重启后仍可复用；网页打开、切回前台及前台每分钟只检查过期项。点击“检查文件状态”跳过缓存，播放和打开访达时也会实时核对该文件。目录离线、权限异常和失效链接不会被当成可清理的缺失文件；扫描/整理/预览生成或音乐分析中暂缓检查。缓存保存的是状态，不复制原始素材。

“失效素材”展示疑似缺失的文件、原路径、原因和检查时间。手动选择记录并确认后，服务端再次核对文件；文件已恢复、路径改变、目录离线或权限异常时保留数据。清理前先将素材信息和关联记录写入应用数据目录 `missing-file-backups/*.jsonl`（权限 `0600`），再事务清理所选素材索引、分类关联、分析缓存、该素材诊断及操作记录，并清理对应版本预览。每次最多 200 条，结果逐项反馈；公共分类、标签和废纸篓记录保留。此操作不删除原文件，备份仅为元数据，没有自动恢复入口，也不是音视频文件备份。在访达中手动改名或移动文件同样会使旧路径失效；重新扫描新路径不会自动继承旧索引的标签及计数。

开发：`npm run dev`；构建：`npm run build`；测试：`npm test`。浏览器验收：`npm run test:browser`（需要 Chrome 和 `npx playwright install webkit`），使用临时副本和独立数据库，不改动真实素材库。服务仅监听 `127.0.0.1`，默认端口 4317，冲突时自动使用后续端口。

项目素材页提供“全部 / 音乐 / 音效 / 照片 / 视频”类型筛选，使用素材当前登记类型，索引已清理时沿用项目快照；不会修改素材分类。类型数量覆盖整个项目的当前候选/已使用状态及关键词搜索结果，不局限于当前分页，也不被当前类型自身锁住。切换类型会清除勾选和重置页码。照片、视频显示按需加载的缩略图，支持项目内大图/视频预览；不兼容或离线时保留类型图标和明确状态。音频支持列表直接试听，完整路径可悬浮查看，访达及移出操作保持不变。

连续试听以独立播放意图控制暂停，不把切歌、音频结束及加载中浏览器短暂的 `paused` 状态当作用户暂停。按暂停立即撤销待执行的自动切歌；后续加载完成、旧的播放回调和跨页响应不会重新播放。暂停保留连续试听偏好，再点播放可继续；末尾结束正常停止。暂停键支持鼠标、触摸、空格和回车，按下暂停后释放不会反向触发播放。浏览器测试覆盖 80/300/800 毫秒短音频、加载中暂停与跨页等待取消。
